# ことば (Kotoba) — แอปเรียนคำศัพท์ญี่ปุ่นด้วย SRS

PWA เรียนคำศัพท์ภาษาญี่ปุ่น ทำงานออฟไลน์ได้ 100% ไม่มี dependency ภายนอก
ไม่ต้องมี build step — เปิด `index.html` ผ่านเว็บเซิร์ฟเวอร์ใดก็ได้ (ต้องเป็น HTTPS
หรือ localhost เพราะ Service Worker และ Notification API บังคับ)

## โครงสร้างไฟล์

```
index.html            หน้าเดียวของแอป มี 4 view: เรียน / บันทึก / สถิติ / ตั้งค่า
style.css             ดีไซน์ทั้งหมด (โทน Muji: กระดาษขาว/หมึกดำ/ตราแดง)
manifest.json         PWA manifest (ติดตั้งลงหน้าจอหลักได้)
sw.js                 Service Worker แคชทุกไฟล์ไว้ใช้ออฟไลน์

js/db.js              ชั้น IndexedDB: words, progress(SRS), favorites, reviewList, reviewLog, settings
js/srs.js              อัลกอริทึม Spaced Repetition (SM-2 แบบย่อ)
js/api.js              ชั้นดึงข้อมูลคำศัพท์ (ตอนนี้อ่านจาก data/*.json → พร้อมสลับไปเรียก backend จริงได้)
js/audio.js             เสียงอ่านด้วย Web Speech API (ไม่ต้องโหลดไฟล์เสียง)
js/notifications.js     การแจ้งเตือนคำศัพท์ใหม่แบบตั้งเวลาได้
js/stats.js             รวมสถิติ สัปดาห์/เดือน/ปี + streak
js/gestures.js          แยกแยะ tap / swipe บนการ์ด
js/app.js               ตัวควบคุมหลัก ผูกทุกอย่างเข้าด้วยกัน

data/words-n5.json ... n1.json   คลังคำศัพท์ แยกตามระดับ (133 คำในชุดเริ่มต้น)
data/categories.json             หมวดหมู่คำศัพท์ 14 หมวด
```

## สถาปัตยกรรมสำคัญ

### SRS (Spaced Repetition)
`js/srs.js` ใช้อัลกอริทึมแบบย่อของ SM-2 (คล้าย Anki): ให้คะแนน 4 ระดับ
(ไม่รู้ / ยาก / จำได้ / ง่าย) แล้วคำนวณ ease factor + ช่วงเวลาก่อนครบกำหนดทบทวนรอบถัดไป
สถานะเก็บใน IndexedDB store `progress` คีย์ด้วย `wordId` — รองรับคำศัพท์นับหมื่นคำ
โดยไม่มีปัญหาประสิทธิภาพ เพราะ query ด้วย index `due`

### การ "อัปเกรด" เป็น backend API จริง
`js/api.js` ออกแบบให้เป็นชั้นกลาง (data-access layer) ไว้แล้ว:
- ตอนนี้ `fetchWordFiles()` อ่านจากไฟล์ในเครื่อง
- ถ้าอยากต่อ backend จริง ให้แก้แค่ฟังก์ชันนี้ให้ `fetch("https://your-api.com/words")`
  แทน — ที่เหลือ (SRS, favorites, สถิติ) ไม่ต้องแตะเลย เพราะแยกชั้นออกจากกัน

### ขยายคลังคำศัพท์ให้ถึง 10,000+ คำ
ชุดเริ่มต้นมี 133 คำ (คัดสรรเอง ครอบคลุม N5–N1 + 14 หมวดหมู่ พร้อมประโยคตัวอย่าง)
เพื่อความถูกต้อง 100% เพราะ AI ไม่ควรสุ่มสร้างคำศัพท์เองหลักหมื่นคำโดยไม่มีแหล่งอ้างอิง
(เสี่ยงผิดทั้งการอ่านและความหมาย) วิธีที่แนะนำให้ขยายจริง:

1. ใช้ **JMdict** (พจนานุกรมญี่ปุ่น-อังกฤษแบบเปิด, ฟรี, อัปเดตสม่ำเสมอ)
   ดาวน์โหลดที่ https://www.edrdg.org/wiki/index.php/JMdict-EDICT_Dictionary_Project
   แล้วเขียนสคริปต์แปลง XML → JSON ตาม schema เดียวกับ `data/words-*.json`:
   ```json
   { "id": "...", "kanji": "...", "hiragana": "...", "katakana": null,
     "romaji": "...", "meaning": "...", "level": "n5",
     "categories": ["daily"], "example_jp": "...", "example_reading": "...", "example_th": "..." }
   ```
2. Meaning ภาษาไทย: JMdict มีคำแปลอังกฤษเป็นหลัก ต้องแปลเพิ่ม (แนะนำใช้ Thai-Japanese
   dictionary dataset เสริม หรือแปลด้วยทีมงาน/นักแปล เพื่อความแม่นยำ)
3. ระดับ JLPT: ใช้ tag ระดับจาก JLPTei/jlpt-vocab-api (โอเพนซอร์สแยกต่างหาก) mapping
   เข้ากับคำใน JMdict
4. แยกไฟล์ JSON ตามระดับ (เหมือนตอนนี้) หรือแบ่งเป็น chunk ละ ~1,000 คำ แล้วให้
   `js/api.js` โหลดแบบ lazy ตามหมวด/ระดับที่ผู้ใช้เลือก จะได้ไม่ต้องโหลดทั้งหมดพร้อมกัน
5. IndexedDB ที่ใช้อยู่ตอนนี้ (ไม่ใช่ localStorage) ออกแบบมารองรับข้อมูลขนาดใหญ่
   อยู่แล้ว — คำหลักหมื่นคำใช้พื้นที่ไม่กี่ MB สบาย ๆ

### การแจ้งเตือน — ข้อจำกัดที่ควรรู้
เว็บแอป (แม้ติดตั้งเป็น PWA แล้ว) **ไม่สามารถส่ง Notification ได้แน่นอน 100%
ขณะที่แอปถูกปิดสนิท** โดยเฉพาะบน iOS Safari ปัจจุบันแอปนี้ทำงานแบบ "best effort":
- เช็คเวลาทุก 1 นาทีเมื่อแอป/แท็บยังเปิดอยู่ (แม้ย่อไปพื้นหลัง)
- ลองใช้ Periodic Background Sync เสริม (รองรับเฉพาะ Chrome/Android ที่ติดตั้งแอปแล้ว)
- ถ้าต้องการแจ้งเตือนแม้ปิดแอปสนิท 100% ต้องมีเซิร์ฟเวอร์ Push จริง (Web Push + VAPID)
  — จุดเชื่อมเตรียมไว้แล้วที่ `Notify.registerPushWithServer()` ใน `js/notifications.js`

## แนวคิดการออกแบบ UI
โทน Muji: กระดาษขาวนวล จุดกริดจาง ๆ แบบสมุดญี่ปุ่น ตราประทับ (hanko) สีแดงบอกระดับ
ตัวอักษร Serif ญี่ปุ่นสำหรับคำศัพท์ พลิกการ์ดด้วย CSS 3D transform (ไม่ใช้ไลบรารี)
ปัดซ้าย/ขวาด้วย Pointer Events ล้วน ๆ (ไม่พึ่ง Hammer.js หรือไลบรารีท่าทางอื่น)
